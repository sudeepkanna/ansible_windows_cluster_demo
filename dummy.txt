PHASE 4 - DYNAMIC ANSIBLE RESULT DATA

This is an important requirement.

AAP job events contain:

event_data.res

The structure of "res" changes depending on the Ansible module.

For example a Windows service module might return:

{
  "changed": false,
  "state": "started",
  "name": "W3SVC"
}

Another module might return:

{
  "changed": true,
  "reboot_required": false,
  "installed_update_count": 4
}

Another module may return nested lists/dictionaries.

I DO NOT want to manually define database columns for every possible Ansible module.

Design the dlt pipeline so that:
- common fields are structured
- dynamic module results are preserved
- nested JSON is not lost
- PostgreSQL JSONB can be used where appropriate
- schema evolution does not continuously break ingestion

Keep the original result payload available for future analysis.
